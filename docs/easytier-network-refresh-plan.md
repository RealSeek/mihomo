# EasyTier underlay network refresh plan

This document describes the underlay refresh required for Wi-Fi/mobile handover
and other address changes. The versioned guest ABI, process-level shared state,
revision-aware cache, Go host update, network-change fan-out and STUN wakeup
described here are implemented. Physical Windows and rooted Android handover
acceptance remains pending device access.

The current Go host sends `platform.EnvironmentSnapshot` once, when a WASM
instance is created. The snapshot is then captured by the Rust guest's
`HostConnectorRuntime`. The existing sing-tun network monitor notices default
interface changes and calls `component/netchange.Notify`, which flushes
interface caches, resets resolver connections, and re-probes mihomo providers.
That notification now refreshes every already-running EasyTier Host through the
versioned guest environment update.

## Goal and boundary

The refresh must update underlay facts in every already-started EasyTier Host
without replacing its core instance, packet sink, WebClient, network UUIDs, or
desired configuration. An offline configuration server must not cause a local
Web-owned network to disappear during a Wi-Fi/mobile handover.

The update covers dynamic observations:

- interface IPv4 and IPv6 addresses;
- local IP addresses;
- preferred global IPv6 source addresses and interface indexes;
- public IPv4/IPv6 observations when the host has them.

The update does not replace static instance declarations. `mapped_listeners`
and `protected_tcp_ports` remain part of the creation-time environment because
they describe listener and process-port ownership, not an underlay address
observation. A later ABI revision may add an explicit static update operation,
but the handover change must not silently alter either field.

The shared TUN remains `stack: mips`; this plan does not broaden its stack
support, enable GSO, or enable AutoRedirect.

## Versioned guest ABI

Add a new versioned JSON envelope in the official Rust WASI source, alongside
`WasiCoreInstanceCreateConfig` and `WasiWebClientCreateConfig`:

```json
{
  "version": 1,
  "revision": 42,
  "environment": {
    "public_ipv4": null,
    "interface_ipv4s": ["192.0.2.10"],
    "public_ipv6": null,
    "interface_ipv6s": ["2001:db8::10"],
    "local_ips": ["192.0.2.10", "2001:db8::10"],
    "preferred_ipv6_sources": [
      {"ip": "2001:db8::10", "ifindex": 7}
    ]
  }
}
```

The exported function should be an instance-independent process operation:

```text
easytier_environment_update(pointer: u32, length: u32) -> i32
```

It must validate the version, revision, address families, and buffer bounds,
then atomically publish the complete snapshot. Revisions are monotonic `u64`
values generated by the Go owner. A stale or duplicate revision is a no-op;
the export must never merge individual address lists with the previous value.
The export returns zero on success and the existing global ABI error status on
validation or lifecycle failure.

The Rust implementation should store one process-level
`Arc<RwLock<EnvironmentState>>` containing `{ revision, dynamic_facts }`. Every
`HostConnectorRuntime` created for a local static instance, a Web-owned
instance, or WebClient receives an `Arc` to that state. Each runtime retains
its own immutable `mapped_listeners` and `protected_tcp_ports` declarations.
The connector environment methods read a consistent dynamic snapshot for one
operation. The shared state must outlive individual instances and must not be
dropped when the configuration server disconnects.

The current Rust `ConnectorHostAdapter` also has a 60-second
`InterfaceAddrCache`. Include the `u64` revision in its cache key alongside
`SocketContext`. Add a default `environment_revision() -> u64` method to the
shared connector runtime trait, override it in the WASI host runtime, and keep
the default value for unchanged native adapters. On collection, verify that
the revision did not change while the address response was obtained before
caching it. A refresh that updates the
underlay but leaves this cache unchanged can continue advertising stale
addresses for up to a minute and is not acceptable for handover.

Add the export to the Rust WASI ABI version table and guest-export list. Keep
the existing create and lifecycle export signatures unchanged. Regenerate the
WASM artifact and the Go ABI wrapper together; a Go-only URL or protobuf change
cannot implement this operation.

The source changes belong in `connectivity/connector_host.rs` for the mutable
observations, `connectivity/composite.rs` for revision-aware caching, and
`wasi/schema.rs`, `wasi/abi.rs`, `wasi/runtime.rs` for the update envelope and
export. `wasi/web_client.rs` must share the process observations rather than
capture a private copy. New static and Web-owned instances read the current
process revision; their creation envelopes must not overwrite newer facts
already installed by an update. `instance/mod.rs` and
`connectivity/direct/mod.rs` can expose the existing STUN refresh notification
without introducing another collector owner.

## Go host ownership and call order

Each Go `Host` owns its process-level environment state and monotonically
increasing revision. It exposes an internal method such as
`UpdateEnvironment(context.Context, platform.EnvironmentSnapshot) error`.
The public mihomo adapter calls this method for every started Host, including
the Host that owns the WebClient. It does not call `OpenPacketSessions`, start
an idle owner, query the configuration server, or recreate an instance.

The update path must follow this order:

1. `component/netchange` flushes the existing mihomo interface cache and
   resets resolver connections, as it does today.
2. The EasyTier coordinator collects one complete dynamic fact snapshot from
   the refreshed interface table and broadcasts it to started Hosts.
3. For each Host, acquire `host.mu` to serialize the revision and creation
   input, then its existing guest serialization (`host.guestMu`) to invoke the
   new guest export. The call copies the JSON into guest memory, invokes the
   export, and reads any error. On success, save the new creation snapshot so
   future instances use the same revision. Release `guestMu`, signal the
   existing instance/WebClient completion channels, then release `host.mu`.
   Do not acquire these locks in the reverse order.
4. The guest atomically publishes the snapshot and invalidates/re-keys its
   interface-address cache. Its existing STUN collector is then signalled to
   redetect immediately. The update does not wait for a full STUN probe or
   block the mihomo network-change callback on a long probe timeout.
5. The coordinator records failures with the owning EasyTier name and revision.
   Retry an uncommitted update on the next network notification; do not claim
   that today's reconnect loop already retries this new operation. A failed
   update must leave the previous complete snapshot intact. Normal host
   recreation collects the current observations again.

`guestMu` is the serialization boundary for WASM calls. Do not hold the
listener, packet mux, DNS registry, or configuration-center management lock
while waiting on a guest call. Conversely, do not update the snapshot from a
second goroutine that can call a guest export concurrently with `Instance`
RPC, packet ingress, or WebClient drive calls.

Creation-envelope reads of `host.options.Services.Snapshot` now occur under
`host.mu`, avoiding a data race between a new instance and an environment
update. The existing instance/WebClient completion channels provide the wakeup
for scheduled guest work; no new Go driver or event queue is required.

The existing Rust `StunInfoCollector` already has an immediate redetection
notification. Wire the new update to that notification after publishing the
snapshot. This causes direct connector address observations and NAT probing to
use the new Wi-Fi/mobile facts without tearing down peer state. Existing manual
connector reconnect loops remain responsible for failed transports.

## Mihomo event integration

Extend the existing `component/netchange` fan-out with an optional EasyTier
stage after `iface.FlushCache` and before provider health checks. The stage
obtains a snapshot once, then broadcasts it to the registry of **already
started** EasyTier Hosts. It must not construct an outbound or call
`ensureStarted`; an idle static outbound and an idle WebClient owner remain
idle.

The sing-tun default-interface callback already invokes `netchange.Notify`.
That callback is emitted when the selected interface changes and when its
address list changes because `control.Interface.Equals` includes addresses.
Linux, Windows, Darwin, and rooted Android therefore share the same event
entry point. The existing Android netlink limitation still applies: the
root/su deployment must provide a usable monitor or another explicit trigger
before it can observe a handover.

The coordinator registry must use owner identity, not proxy list position. A
WebClient owner may expose multiple remote network UUIDs; one environment
update is sent to its single Host. Removing a mihomo proxy unregisters the Host
after its normal close path. A concurrent close may race an update; the update
must return the existing closed error and must not resurrect the Host.

Use a small internal capability interface in the network-change fan-out, then
walk the existing proxy owners and deduplicate their started Host identities.
Keep that capability independent of EasyTier protobuf or WASM types so the
existing package dependencies and `no_easytier` build remain valid. There is no
need for another general event bus. If the listener's existing adapter list is
used for attached owners, preserve the same rule: notify through the cached
owner reference and let the owner report its already-started Host.

## Failure and offline behavior

An environment update is a host-fact update, not a configuration-center
mutation. It must continue to work while the WebClient is disconnected or the
configuration server is unavailable. No `RunNetworkInstance`, retain, delete,
or overwrite request is sent.

The existing WebClient reconnect loop keeps its machine identity and desired
network state. The update must not call `Host.Close`, `WebClient.Close`,
`Instance.Close`, or `Host.CreateInstance`. Packet mux receivers, DNS records,
route ownership, and network UUIDs therefore remain intact while the underlay
changes.

## Required implementation checks

The following checks are required after the Rust artifact and Go wrapper are
rebuilt:

1. **ABI validation:** create a core with a known snapshot, update it with
   revision 2, reject revision 1, reject malformed address families, and prove
   the previous complete snapshot remains after rejection.
2. **Cache invalidation:** call connector `collect_ip_addrs` before and after
   an update without waiting 60 seconds; the second response must contain only
   the new revision's addresses.
3. **STUN refresh:** use a deterministic STUN fixture and prove an underlay
   update wakes immediate redetection rather than waiting for the normal
   interval. Verify the new source address is used by the next observation.
4. **Guest serialization:** race environment updates with packet ingress,
   instance management RPC, and WebClient drive calls under the Go race
   detector; no concurrent WASM call or guest-memory corruption is allowed.
5. **Idle ownership:** create an EasyTier outbound but do not open a packet
   session; a network-change notification must not start its Host or WebClient.
6. **Web offline retention:** with two Web-owned networks running, disconnect
   the configuration server, trigger an environment update, and verify both
   network UUIDs, packet mux receivers, routes, and Magic DNS records remain.
   Reconnect afterward and verify desired-state reconciliation still works.
7. **Replacement interaction:** perform a server-driven same-UUID replacement
   during an underlay update. The replacement must receive the newest snapshot
   revision and the old receiver must be removed exactly once.
8. **Physical acceptance:** on Windows and a rooted Android phone, switch
   Wi-Fi to mobile data and back. Verify one TUN per device, peer traffic,
   Magic DNS, source addresses, NAT/relay recovery, and cleanup. This remains
   pending until the devices are available.

These tests prove dynamic host-fact refresh. They do not by themselves prove
that every upstream transport is supported by the WASM host; FakeTCP, network
namespaces, and WebSocket configuration endpoints remain separate capability
boundaries.
